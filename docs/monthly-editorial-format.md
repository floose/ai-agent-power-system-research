# Monthly research writing format

The reader-facing Markdown report and newsletter contain only a short editorial lead, paper briefs and a compact cross-paper interpretation. Each brief includes the linked title, journal and date, main idea, supported results, an AI relevance assessment explicitly separated from author findings, and source/evidence links. Use accessible engineering language, concise English and consistent scientific terminology. Explain specialized methods when necessary.

Do not include software execution details, Python versus web retrieval, workflow/PR mechanics, internal triage labels or process checklists in reader-facing research Markdown. Keep provenance, source versions, reading status, unresolved verification and execution details in the JSON companion. Briefly mention abstract-only evidence or other scientific limitations when they affect the meaning of results; never conceal those limits.

Use the canonical hashtags in config/hashtags.json, extending the catalog only when a new supported subject or method requires it. Store per-paper hashtags and keywords in the JSON companion, preserving DOI identity. This prepares structured material for future analysis; do not build a dashboard now. Hashtags are indexing aids, not evidence of a trend.

Reuse the same evidence-backed analysis for newsletters and reports; do not repeat retrieval or model reading merely to generate another presentation. Preserve source references and units. Do not invent outcomes or operational benefits. Published means proposed through a GitHub PR unless merge has been separately authorized.
